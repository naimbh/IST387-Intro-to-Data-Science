Skills a data scientist needs

In plain wordsData science means using math, statistics, coding and knowledge of the field to turn data into actionable insights: findings that someone can act on, such as “stock more umbrellas in July”. No single skill is enough, so the job is multidisciplinary (it mixes several fields).

Everyday example

A good doctor uses several skills at once.

She knows the body (field knowledge), orders blood tests (data), reads the numbers (statistics), uses machines and software (tools), and finally explains the result so the patient understands (communication). A data scientist works the same way.

SkillWhat it meansExample

Remember for the exam: the course says that, above all, data science is about communicating. Curiosity, critical thinking and ethics also count as skills.

A data science project: domain analysis and SMEs

In plain wordsBefore you touch the data, learn the domain: the real-world field the data comes from, such as a hospital, a shop or a bike-share system. The fastest way to learn it is to talk to SMEs (subject matter experts): people who know that field from experience. Then you work through the project in steps, and you usually go round the steps more than once.

Everyday example

Building a house for a family.

An architect doesn't start drawing right away. First she asks the family how they live: how many children, whether grandparents visit, where they cook. The family members are the SMEs. Without them, the house might look nice but not work for them.

A worked example: “Why did online orders drop?”

Say you analyze orders for an online shop built in Laravel. Here is the project, step by step, using the OSEMN process (say it “awesome”).

StepWhat you doIn the shop project
ObtainGet the dataExport the orders table from MySQL
ScrubClean it (usually the longest step, often over half the work)Remove test orders, fix missing prices, convert dates
ExploreLook at it with charts and summary numbersA line chart of orders per day shows a sudden drop
ModelBuild a model that explains or predictsPredict next month's orders
iNterpretExplain what it means and what to doTell the manager: “Orders fell because checkout broke on phones”

Where the SME helps: you notice a day with zero orders. That's an anomaly (a value that doesn't fit the pattern). An anomaly is either an error (the website was down) or an interesting exception (a public holiday). The sales manager, your SME, can tell you which one it is. Ask SMEs to tell stories about their work; the stories reveal what the data means.

CRISP-DM (Cross-Industry Standard Process for Data Mining) is another process model. It starts with business understanding, which is the same idea as domain analysis. Both models loop: what you learn in a later step often sends you back to an earlier one.

UnstructuredNo table shapeText reviews, photos, audio, video (there's far more of this in the world)

The real-world area the data is about.

Subject matter expert: someone who knows the domain deeply, such as a nurse, a store manager or a mechanic.

Obtain, Scrub, Explore, Model, iNterpret. Scrub (cleaning) takes the most time.
Short answerWhat is an SME, and why should you talk to one at the start of a project?
A subject matter expert. They explain how the domain works, what the data means, and whether an odd value is an error or a real exception.

R's data structures: vector, list and data frame

In plain wordsR stores data in three main containers. A vector is a row of values that are all the same type. A list can hold different types together. A data frame is a table: several vectors of the same length, standing side by side as columns.

Everyday example

Think of an Excel file.

One column of marks is a vector. The whole sheet is a data frame. A list is more like your wallet: it holds cash, a card and a photo, which are different kinds of things.

The four basic types (R calls them modes)

TypeExampleNote
logicalTRUE, FALSEYes/no. TRUE counts as 1 and FALSE as 0.
numeric (double)2.5, 90Any number.
integer5LWhole numbers; the L makes it an integer.
character"Meem"Text, always in quotes.

Vector

scores <- c(90, 85, 70)     # c() = combine; <- = store in a name
scores[2]                    # 85   (R counts from 1, not 0)
length(scores)               # 3

A vector can hold only one type. If you mix types, R converts everything to the most flexible one: logical → numeric → character. This is called coercion.

c(1, "a", TRUE)    # "1" "a" "TRUE"   (one text value turns everything into text)
c(1, TRUE, FALSE)  # 1 1 0            (TRUE becomes 1, FALSE becomes 0)

List

me <- list(name = "Meem", scores = c(90, 85), passed = TRUE)
me$scores          # 90 85
length(me)         # 3   (three items of three different types)
me[["name"]]       # "Meem"  (double brackets take the item out)

Changing vectors and data frames

In plain wordsMost exam code questions ask you to pick, add, change, remove or sort parts of a vector or a table. Square brackets [ ] pick parts by position. For tables, use [row, column]: rows go before the comma and columns after it.

Everyday example

Editing a class register.

You add a new student (add a row), cross one out (remove a row), add a column for “passed” (add a column), correct a wrong mark (change a value), and finally sort the list from the highest mark to the lowest.

Vectors

x <- c(5, 3, 8)
x <- c(x, 10)      # add to the end       →  5 3 8 10
x[2] <- 4          # change element 2     →  5 4 8 10
x <- x[-1]         # remove element 1     →  4 8 10   (minus = "everything except")

sort(c(30, 10, 20))                      # 10 20 30   (the values, in order)
sort(c(30, 10, 20), decreasing = TRUE)   # 30 20 10
order(c(30, 10, 20))                     # 2 3 1      (the POSITIONS in sorted order)

Data frames: picking parts

class_df[2, ]            # row 2, all columns:   Mitu  B  95
class_df[ , "score"]     # one column as a vector:  72 95 88 64
class_df$score           # the same thing, shorter
class_df$score[3]        # one cell: 88

Adding, changing and removing

df <- class_df
df$passed <- df$score >= 70    # ADD a column (TRUE/FALSE for each student)
#     name section score passed
# 1   Rafi       A    72   TRUE
# 2   Mitu       B    95   TRUE
# 3 Tanvir       A    88   TRUE
# 4  Anika       B    64  FALSE

df$passed <- NULL              # REMOVE a column
df$score[1] <- 75              # CHANGE one value (Rafi now has 75)

df <- rbind(df, data.frame(name = "Sumi", section = "A", score = 81))   # ADD a row
df[-5, ]                       # every row EXCEPT row 5 (Sumi)

Sorting, filtering, grouping and summarizing

Each job can be done two ways: with base R (built in) or with the tidyverse (the dplyr package, loaded with library(tidyverse)). The pipe %>% means “then”.

# Sort from highest to lowest score
df[order(-df$score), ]                 # base R  (minus sign = descending)
df %>% arrange(desc(score))            # tidyverse

# Keep section A, show name and score only
df %>% filter(section == "A") %>% select(name, score)
#     name score
# 1   Rafi    75
# 2 Tanvir    88
# 3   Sumi    81

# Average score per section
df %>% group_by(section) %>% summarize(avg = mean(score), n = n())
#   section   avg     n
# 1 A        81.3     3
# 2 B        79.5     2

# Add 5 marks to everyone (a new column)
df %>% mutate(curved = score + 5)

Exam trap

sort() gives the values; order() gives the positions. To sort a whole table in base R, you need order() inside the row slot: df[order(df$score), ].

Also: select() keeps columns and filter() keeps rows. If you select() away a column, a later filter() can't use it.

Logical operations and subsetting

In plain wordsA logical operation asks a yes/no question about every value at once and gives back a TRUE or FALSE for each one. When you put those TRUE/FALSE answers inside square brackets, R keeps only the TRUE ones. Keeping only some values or rows like this is called subsetting.

Everyday example

A guard at a wedding gate.

The guard checks each guest against one rule, say “is on the guest list”. Each guest gets a yes or a no. Only the guests with a yes go inside. In R, the rule is the comparison, and the square brackets are the gate.

SymbolMeansExampleAnswer
==is equal to5 == 5TRUE
!=is not equal to5 != 5FALSE
> < >= <=bigger, smaller, at least, at most3 >= 3TRUE
&AND: both must be TRUETRUE & FALSEFALSE
|OR: at least one is TRUETRUE | FALSETRUE
!NOT: flips the answer!TRUEFALSE
%in%is it one of these?"A" %in% c("A", "B")TRUE

On a vector

s <- c(72, 95, 88, 64)
s > 80                # FALSE  TRUE  TRUE FALSE   (one answer per value)
s[s > 80]             # 95 88                     (keep the TRUE ones)
sum(s > 80)           # 2      (TRUE counts as 1, so this COUNTS the TRUEs)
which(s > 80)         # 2 3    (the POSITIONS of the TRUEs)
s > 70 & s < 90       # TRUE FALSE TRUE FALSE     (between 70 and 90)
s < 70 | s > 90       # FALSE TRUE FALSE TRUE     (below 70 OR above 90)
any(s > 90)           # TRUE   (is at least one TRUE?)
all(s > 60)           # TRUE   (is every one TRUE?)

On a data frame

Put the test before the comma, because it picks rows. Refer to columns with $.

class_df[class_df$section == "A" & class_df$score > 80, ]
#     name section score
# 3 Tanvir       A    88

class_df$name[class_df$score == max(class_df$score)]   # "Mitu"
class_df[class_df$section %in% c("A"), "name"]          # "Rafi" "Tanvir"
Exam trap
  • = is not ==. One equals sign names an argument; two equals signs ask “are these equal?”.
  • class_df[class_df$score > 80] without the comma doesn't keep rows; it treats the test as picking columns. Write class_df[class_df$score > 80, ].
  • if can check only one TRUE/FALSE. For a whole column, use ifelse(), or wrap the test in any() or all().
New words
logical vector
A vector of TRUE/FALSE values, one per element.
subsetting
Keeping only some elements or rows.
which()
Returns the positions where a test is TRUE.
%in%
Checks whether each value appears in a list of allowed values.
Try it like the exam
Outputx <- c(4, 8, 1, 6). What do x[x > 5] and sum(x > 5) return?
8 6, then 2.
OutputWhich students does class_df[class_df$section == "B" | class_df$score > 85, ] return?
Mitu (section B), Tanvir (88 > 85) and Anika (section B). Only Rafi fails both tests.
OutputWhat does !(c(TRUE, FALSE) & TRUE) return?
First c(TRUE, FALSE) & TRUE is TRUE FALSE. The ! flips it: FALSE TRUE.

Writing a simple function

In plain wordsA function is a saved recipe. You give it inputs (called arguments), it runs the steps inside the curly brackets, and it hands back an answer (the return value). R returns the value of the last line automatically, so return() is optional.

Everyday example

A calculator button.

The √ button is a function: you give it 16, and it gives back 4. You don't care how it works inside; you just reuse it. Writing your own function is making your own button. This follows the rule DRY: don't repeat yourself.

grade <- function(score) {               # name <- function(inputs) {
  ifelse(score >= 70, "pass", "fail")    #   the steps; the last line is returned
}                                        # }

grade(c(72, 64))      # "pass" "fail"

Default arguments: you can give an argument a value to use when the caller leaves it out.

area <- function(w, h = 2) {
  w * h
}
area(3)       # 6    (h uses the default, 2)
area(3, 4)    # 12

Scope: which value does the function see?

Scope means where a name can be seen. An argument always wins over an outside variable with the same name. If the function uses a name it was never given, R looks outside the function for it.

x <- 2
z <- 3
f <- function(z) {
  z * x
}
f(x)     # 4

Trace it: f(x) sends the value 2. Inside, z is 2 (the outside z <- 3 is hidden). x isn't an argument, so R finds the outside x, which is 2. So 2 × 2 = 4.

New words
argument
An input to a function.
return value
What the function hands back.
scope
Where in your code a name is visible.
DRY
Don't repeat yourself: write the code once, reuse it.

Write codeWrite a function doubleIt that takes a number and returns it times 2.

  x * 2
}
doubleIt(5) gives 10.

  population / area
}
It also works on whole columns: popDensity(df$pop, df$area).

Descriptive statistics

In plain wordsDescriptive statistics are numbers that describe the data you already have. They answer two questions: what's typical? (the center) and how spread out are the values? (the spread). They don't predict anything; predicting is inferential statistics.

Everyday example

Daily pay at a small shop in a bazaar.

Four workers earn ৳300, ৳400, ৳500 and ৳500 a day. The owner pays himself ৳3,000. What does a “typical” person here earn? The average says ৳940, but nobody except the owner earns that much. The middle value says ৳500, which matches most people. That's why we need more than one measure.

pay <- c(300, 400, 500, 500, 3000)

mean(pay)       # 940     the average: add them up, divide by 5
median(pay)     # 500     the middle value once sorted
range(pay)      # 300 3000   smallest and biggest
sd(pay)         # 1154.6  standard deviation: typical distance from the mean
IQR(pay)        # 100     spread of the middle half (Q3 - Q1 = 500 - 400)
quantile(pay)
#   0%  25%  50%  75% 100%
#  300  400  500  500 3000
summary(pay)
#  Min. 1st Qu. Median  Mean 3rd Qu.  Max.
#   300     400    500   940     500  3000
MeasureQuestion it answersHerePulled by the owner's ৳3,000?
MeanWhat's the average?940Yes, a lot
MedianWhat's in the middle?500No
ModeWhat value appears most often?500No
RangeHow far apart are the smallest and biggest?3000 − 300 = 2700Yes

The lesson: one extreme value, called an outlier, drags the mean and the sd but barely moves the median and the IQR. When the data has outliers (salaries, house prices, populations), the median describes the typical case better.

Variance and sd by hand

var(c(2, 4, 6))   # 4
sd(c(2, 4, 6))    # 2
  1. Mean: (2 + 4 + 6) / 3 = 4.
  2. Distance of each value from the mean: −2, 0, 2.
  3. Square them: 4, 0, 4. Add them up: 8.
  4. Divide by n − 1 (R treats your data as a sample): 8 / 2 = 4. That's the variance.
  5. Square root: √4 = 2. That's the sd, back in the original units.
Exam trap

mode(pay) returns "numeric", the type of the data, not the most common value. R has no built-in function for the statistical mode; one way is names(which.max(table(pay))), which gives "500".

How randomness affects sampling

In plain wordsThe population is everything you want to know about, such as all voters in the US. You usually can't measure all of it, so you measure a sample: a part of it, picked at random. Because the pick is random, every sample comes out a little different, so its mean is a little different too. This is called sampling variability. Bigger samples vary less, so they're more reliable.

Everyday example

Tasting a pot of soup.

You taste one spoonful to judge the whole pot. One spoonful might be saltier than another just by chance. A bigger spoonful (a bigger sample) tells you more reliably how the whole pot tastes. And you stir first, so every part has an equal chance to be in the spoon. That stirring is what random sampling means.

Rolling a die in R

set.seed(1)
sample(1:6, 5, replace = TRUE)   # 1 4 1 2 5
set.seed(1)
sample(1:6, 5, replace = TRUE)   # 1 4 1 2 5   ← the same seed gives the same "random" rolls
set.seed(2)
sample(1:6, 5, replace = TRUE)   # 5 6 6 1 5   ← a different seed, different rolls

A fair die averages 3.5 in the long run. Here's what the average looks like with small and big samples:

# Three samples of only 5 rolls each: the means jump around
# 2.0   3.6   3.8

# One sample of each size:
#     10 rolls → 2.80
#    100 rolls → 3.55
#  1,000 rolls → 3.48
# 100,000 rolls → 3.49    ← very close to the true 3.5

Coin flips: rbinom(10, 1, 0.5) makes 10 random 0s and 1s, like 10 coin flips. The result changes every run unless you set a seed.

New words
population
Everything you want to study.
sample
The part you actually measure.
random sample
Every member had an equal chance to be picked.
sample(x, size, replace)
Picks size random values from x. With replace = TRUE, each pick is put back first, so a value can be picked again.
set.seed()
Fixes R's random starting point, so the same “random” numbers come out every time. This makes your work repeatable.
rbinom(n, size, prob)
Random results for yes/no events, such as coin flips: n results, size tries each, prob chance of a yes.
Try it like the exam
Short answerTwo students each draw a random sample of 10 from the same data. Their means differ. Did someone make a mistake?
No. Random samples naturally differ. That's sampling variability. Bigger samples would make their means closer.
Short answerWhat does replace = TRUE mean in sample()?
Each drawn value is put back before the next draw, so the same value can come up more than once.
Short answerWhy use set.seed()?
So the random results are the same every time you (or your instructor) run the code. That makes the work reproducible.

Sampling distributions, the LLN and the CLT

In plain wordsA sampling distribution is what you get when you take many samples, compute the mean of each one, and collect all those means. Two rules describe it. The Law of Large Numbers (LLN) is about accuracy: with more data, the average gets closer to the true value. The Central Limit Theorem (CLT) is about shape: the sample means form a bell curve, even when the original data is lopsided.

Everyday example

Many classes taking the same test.

Imagine 2,000 schools each pick 16 random students and report their class average. Most averages land near the national average; a few are unusually high or low. If you draw a histogram of the 2,000 averages, it looks like a bell. That histogram is the sampling distribution.

The course example: state populations

pop <- state.x77[ , 1]      # 50 state populations (in thousands)
mean(pop)                   # 4246.42   the true population mean
median(pop)                 # 2838.5

means <- replicate(2000, mean(sample(pop, 16, replace = TRUE)))
length(means)               # 2000      one mean per sample
mean(means)                 # 4256      very close to 4246 (LLN)
hist(means)                 # a bell shape (CLT)
quantile(means, c(0.025, 0.975))
#     2.5%    97.5%
#  2366.8   6648.8            the middle 95% of sample means

Your numbers will differ slightly, because the samples are random. These come from set.seed(42).

Using it to judge a mystery sample

Someone gives you 16 numbers and claims they're state populations. Their mean is 2,276. Is that believable?

  1. Build the comparison distribution: the 2,000 sample means above.
  2. Mark the middle 95%: from 2,367 to 6,649. Anything outside is “extreme”.
  3. Compare: 2,276 is below 2,367, so it's in the extreme zone.
  4. Conclude (tentatively): these 16 numbers probably did not come from the state populations.

Drawing and reading a histogram

In plain wordsA histogram shows how one numeric variable is spread out. R splits the number line into equal ranges called bins, counts how many values fall in each bin, and draws one bar per bin, as tall as that count. The shape of the bars tells you the story.

Everyday example

Grouping exam marks.

A teacher counts how many students scored 0–10, 10–20, 20–30 and so on, then draws a bar for each range. Tall bars show where most students landed. That's a histogram.

hist(pop)                          # base R, default bins
hist(pop, breaks = 20)             # ask for about 20 thinner bins
ggplot(data.frame(pop), aes(x = pop)) + geom_histogram(bins = 10)   # ggplot2 version

hist(rnorm(500, mean = 50, sd = 10))   # 500 random values from a bell curve

In the left chart in section 9, the tallest bar on the far left says 17 states had under 2 million people. Only a handful of bars sit far to the right (California, New York, Texas). That long tail on the right makes it right-skewed, and the mean (4.2 M) is pulled above the median (2.8 M).

ggplot2: making charts and picking the right one

In plain wordsIn ggplot2, every chart is built from three parts joined with +: the data (which table), the aesthetics (which column goes on x, y, color and so on, written inside aes()) and the geometry (what to draw: points, bars, lines, written as geom_…()).

Everyday example

Making a sandwich in layers.

First the bread (the data), then you decide what goes where (aes: cheese here, tomato there), then the style of sandwich (the geom). You can keep adding layers with +, like adding lettuce on top.

library(ggplot2)

ggplot(mtcars, aes(x = wt, y = mpg)) + geom_point()            # scatter: weight vs mpg
ggplot(mtcars, aes(x = wt, y = mpg, color = factor(cyl))) +
  geom_point()                                                   # color the dots by cylinders
ggplot(mtcars, aes(x = mpg)) + geom_histogram(bins = 8)          # histogram of one number
ggplot(mtcars, aes(x = factor(cyl), y = mpg)) + geom_boxplot()   # mpg for each cylinder group
ggplot(mtcars, aes(x = factor(cyl))) + geom_bar()                # bar chart: counts cars per group
ggplot(economics, aes(x = date, y = unemploy)) + geom_line()     # line chart over time

factor(cyl) tells ggplot to treat 4, 6 and 8 cylinders as categories, not as a number scale.

Rules the course teaches

  • Position is easiest to read, color shading is hardest (Cleveland and McGill's ranking). That's why bar, line and scatter charts are the workhorses.
  • Bar charts start at zero, or they exaggerate differences.
  • Avoid 3D pie charts: angles and volumes are hard to judge, and 3D distorts them. ggplot has no geom_piechart() on purpose.
  • Keep it simple (Tufte): cut clutter.
  • Don't rely on color alone: many people are color-blind.
Exam trap
  • Layers join with +, not %>%. The pipe can only feed the data into ggplot().
  • geom_point without parentheses is an error; write geom_point().
  • A fixed color goes outside aes(): geom_point(color = "red"). A color that depends on a column goes inside: aes(color = cyl).
  • fill is the inside color of a bar; color is its outline.
  • geom_bar() counts rows for you; geom_col() uses a y value you already calculated.

Maps in R

In plain wordsTo R, a map is just a big table of points. Each row is one point on a border, with its longitude (east–west position) and latitude (north–south position). ggplot connects the points of each shape in order, like connect-the-dots, and fills them in. To color states by a value, you join your data to that table first.

Everyday example

A connect-the-dots puzzle.

The page has numbered dots. Join them in order and a shape appears. map_data("state") is the list of dots for every US state: order is the dot number and group says which shape each dot belongs to.

merged <- merged %>% arrange(order)                                     # merge shuffles rows: fix it
ggplot(merged) +
  geom_polygon(aes(x = long, y = lat, group = group, fill = area), color = "black") +
  coord_map()

Map ideas the exam can ask about

  • A data map needs at least three fields: latitude, longitude and a value to show.
  • A projection flattens the round Earth onto paper, and every projection distorts something. Mercator keeps directions (good for ships) but makes areas near the poles look huge (Greenland, Alaska).
  • Four kinds of spatial data: point, line, polygon (an enclosed area) and raster (a grid of cells, like pixels).
  • Vector maps draw lines between points (what ggplot does); raster maps are images made of pixels (map tiles).
  • Geocoding turns an address into latitude and longitude (Google Maps, OpenStreetMap).
Exam trap
  • Forgetting tolower(): "New York" doesn't match "new york", so the merge silently drops those states.
  • Forgetting arrange(order) after merge(): the dots are joined in the wrong order and the states look like spaghetti.
  • Forgetting group = group: all states get joined into one tangled shape.
  • A squashed, too-wide map means coord_map() is missing.

A map where each area is filled with a color based on a value.

Types of machine learning and prediction problems

In plain wordsMachine learning means the computer learns patterns from examples instead of being given the rules. There are three main types. In supervised learning, the examples come with the right answers. In unsupervised learning, there are no answers, and the computer finds groups on its own. In reinforcement learning, it learns by trial and error from rewards.

Everyday example

Supervised: studying with an answer key.

You practice past papers that have the answers, then you can answer new questions. The answers are called labels.

Everyday example

Unsupervised: sorting a box of old photos.

Nobody tells you the groups. You notice on your own that some are weddings, some are school trips and some are Eid.

Everyday example

Reinforcement: training a pet.

The dog gets a treat for sitting and nothing for jumping. Over time it learns which actions earn rewards.

Predictive models: train, use, interpret and evaluate

In plain wordsBuilding a model has three steps: train it on examples where you know the answer, test it on examples it has never seen, then use it to predict new cases. You test on unseen data because a model can memorize its training data and still fail in the real world.

Everyday example

Studying for this exam.

If you only memorize the answers to one practice paper, you'll score 100% on that paper and badly on the real exam. That's overfitting. If you only learn one rule, like “always pick (c)”, you'll do badly everywhere. That's underfitting. The real exam is the test set: questions you haven't seen.

A. Splitting into training and testing data

library(caret)
set.seed(110)
trainList <- createDataPartition(y = titanic$Survived, p = 0.80, list = FALSE)
trainSet  <- titanic[trainList, ]     # 80% of the rows: the model learns from these
testSet   <- titanic[-trainList, ]    # the other 20%: held back to check it

createDataPartition() picks 80% of the row numbers at random, while keeping the same mix of outcomes (survived/died) in both sets.

B. Linear regression with lm() (predicts a number)

Question: do heavier cars use more fuel? Predict mpg from wt (weight in 1,000 lb).

model <- lm(mpg ~ wt, data = mtcars)    # predict mpg FROM wt
summary(model)
#              Estimate  Std. Error  t value  Pr(>|t|)
# (Intercept)   37.2851      1.8776   19.858   < 2e-16 ***
# wt            -5.3445      0.5591   -9.559  1.29e-10 ***
# Multiple R-squared: 0.7528
Part of the outputWhat it means here
mpg ~ wtThe ~ means “predicted from”. Left: what you predict (the dependent variable). Right: the predictor (the independent variable).
Intercept 37.29The predicted mpg for a car weighing 0. It's the starting point of the line, and usually not interpreted.
wt −5.34 (the coefficient, or slope)Each extra 1,000 lb goes with about 5.3 fewer miles per gallon.
Pr(>|t|) 1.29e-10 (the p-value)Far below 0.05, so weight is a significant predictor. 1.29e-10 means 0.000000000129. The stars *** say the same thing.
R-squared 0.75Weight explains about 75% of the differences in mpg between cars.

The equation: predicted mpg = 37.29 − 5.34 × wt. For a car weighing 3 (3,000 lb): 37.29 − 5.34 × 3 = 21.25.

predict(model, newdata = data.frame(wt = 3))      # 21.25

model2 <- lm(mpg ~ wt + hp, data = mtcars)          # two predictors, joined with +
# Adjusted R-squared: 0.81   (better than 0.75 with weight alone)
predict(model2, data.frame(wt = 3, hp = 150))       # 20.83

Adjusted R² is like R², but it penalizes predictors that don't help. Use it to compare models with different numbers of predictors.

C. Decision trees with rpart() (predicts a category)

A decision tree is a chain of yes/no questions, like a flowchart. For the Titanic, it might ask “Is the passenger male?”, then “Is the passenger an adult?”, and end with a prediction: survived or died. It's easy to explain to a manager.

library(rpart); library(rpart.plot)
cartTree <- rpart(Survived ~ ., data = trainSet)      # . = use every other column
prp(cartTree)                                          # draw the tree
predict(cartTree, newdata = testSet, type = "class")   # labels: No / Yes
predict(cartTree, newdata = testSet)                   # probabilities instead

D. Support vector machines with ksvm() (predicts a category)

An SVM draws the boundary between two classes with the widest possible gap (the margin). The hardest cases, sitting right on the edge of the gap, are the support vectors. With the kernel trick, an SVM can bend the boundary into a curve. SVMs often predict well but are hard to explain (a “black box”).

library(kernlab)
svmModel <- ksvm(Class ~ ., data = trainSet, C = 5, cross = 3, prob.model = TRUE)
svmPred  <- predict(svmModel, testSet)

cross = 3 runs cross-validation: split the training data into 3 parts, train on 2, test on the third, and repeat 3 times. The cross-validation error is the best guess of real-world error.

E. Evaluating a classifier: the confusion matrix

A spam filter checks 100 emails. 20 are really spam and 80 are not. A confusion matrix counts each kind of right and wrong answer:

Really spamReally not spam
Predicted spam15 ✓ caught10 ✗ false alarm
Predicted not spam5 ✗ missed70 ✓ correct
  • Accuracy = correct ÷ total = (15 + 70) ÷ 100 = 0.85. The correct answers sit on the diagonal: sum(diag(cm)) / sum(cm).
  • No Information Rate (NIR) = the accuracy of always guessing the most common class. Always guessing “not spam” is right 80 ÷ 100 = 0.80 of the time.
  • So the model is only 5 points better than lazy guessing. In confusionMatrix() output from caret, P-Value [Acc > NIR] below 0.05 means the model is significantly better than guessing.
  • Sensitivity = how many real positives it caught: 15 ÷ 20 = 0.75.
cm <- table(predicted, actual)                 # build the matrix yourself
sum(diag(cm)) / sum(cm)                         # accuracy
confusionMatrix(predictions, testSet$Survived)  # caret: matrix + accuracy + NIR + p-value
Exam trap
  • predict(model, wt = 3) doesn't error, but it ignores wt = 3 and returns the 32 fitted values. Always pass a data frame: predict(model, newdata = data.frame(wt = 3)).
  • The new data frame must use the same column names as the model's predictors.
  • Accuracy measured on the training data is too optimistic. Judge a model on the test set.
  • A coefficient shows a relationship, not a cause. Correlation is not causation.

Exam-morning checklist

The traps that cost the most marks. Read these once more before you walk in.

  1. df[rows, columns]: the test that picks rows goes before the comma.
  2. R counts from 1. A minus index means “everything except”.
  3. length(df) counts columns; nrow(df) counts rows.
  4. sort() gives values; order() gives positions.
  5. == compares; = names an argument; <- stores.
  6. if takes one TRUE/FALSE; ifelse() works on a whole column.
  7. mean() returns NA if anything is missing. Add na.rm = TRUE.
  8. mode() gives the type, not the most common value.
  9. Mean > median → right-skewed.
  10. LLN = accuracy; CLT = bell shape.
  11. ggplot layers join with +; geoms need ().
  12. Maps: tolower() before merging, arrange(order) after, coord_map() to un-squash.
  13. predict(model, newdata = data.frame(...)), with the same column names.

Part 1 · Weeks 1–3

R basics, data frames and descriptive statistics

Vectors: R's arrays

A vector holds values of one type. Math runs on every element at once, with no loop needed.

x <- c(4, 8, 15)
x[2]        # 8   (counting starts at 1)
x * 2       # 8 16 30
x[-1]       # 8 15 (minus means "drop element 1")
length(x)   # 3

Exam trap: mix types and R turns everything into text. c(3, "a", TRUE) becomes "3" "a" "TRUE", so mode() says "character".

The data types (modes) to know: numeric, character, logical (TRUE/FALSE). sum(c(TRUE, FALSE, TRUE)) is 2, because TRUE counts as 1.

New in this code
x <- …
<- stores a value in a name, like $x = … in PHP. Read it as “x gets”.
c()
combine: joins values into one vector, R's simple list of same-type values.

Everything after # on a line is a comment. R ignores it.
x[2]
Square brackets pick elements by position. R counts from 1, so x[2] is the second value, 8.
x * 2
Vector math: R doubles every element at once, with no loop.
x[-1]
A minus sign inside the brackets means “everything except”: here, all but the first element.
length()
How many elements a vector has, like count($arr) in PHP.
mode()
Returns the data type of a vector: "numeric", "character" or "logical". It does not find the most common value.
sum()
Adds up all the values. TRUE counts as 1 and FALSE as 0.

Data frames and [row, col] indexing

name  <- c("Ana", "Ben", "Cy")
score <- c(70, 92, 85)
df <- data.frame(name, score)

df[2, ]            # row 2, all columns  → Ben 92
df[ , "score"]     # the whole score column
df$score[3]        # 85
df[df$score < 90, "name"]   # "Ana" "Cy"  (a WHERE inside the brackets)
SQL brain: df[rows, cols]. A blank before the comma means every row, and a blank after it means every column.

Look at a data frame with str(df), summary(df) (min, quartiles, mean, max for each column), head(df), nrow(df) and View(df).

Tidyverse verbs: the query builder

df %>% filter(score > 80)        # Ben, Cy
df %>% arrange(desc(score))      # Ben, Cy, Ana
df %>% select(name)

Descriptive statistics

  • Center: mean() is the average, which outliers pull around. median() is the middle value, which outliers don't affect. R has no built-in mode function.
  • Spread: sd() is the standard deviation, var() the variance (sd²), and range() the min and max.
  • Shape: hist(x) shows the distribution. If it's skewed (a long tail), report the median.
  • Random data: rnorm(n, mean, sd) makes normal data; set.seed(1) makes randomness repeatable.
v <- c(2, 4, 4, 10)
mean(v)    # 5
median(v)  # 4   (the outlier 10 pulls the mean up, not the median)

Part 2 · Weeks 4–7

Sampling, getting data, charts and maps

Population vs. sample

The population is everyone (all 50 states). A sample is the part you actually measure. We use samples to guess things about the population, which is called inference. Here the question is: if you measured only 16 random states, how close would their average population be to the true average of all 50?

stateDF <- data.frame(state = state.name, population = state.x77[, "Population"])
mean(stateDF$population)                       # 4246.42, the true mean of all 50
sample(stateDF$population, size = 16)          # 16 random states
mean(sample(stateDF$population, size = 16))    # one sample mean
replicate(2000, mean(sample(stateDF$population, 16)))  # 2000 sample means
rbinom(n = 8, size = 1, prob = 0.5)            # 8 coin flips: 0/1
Think of replicate() as a loop that runs the same line 2000 times and collects every result into a vector.
New in this code
stateDF
A data frame with one row per US state: its name and its 1975 population in thousands. The first line builds it from two tables that come with R: state.name (the 50 names) and state.x77 (facts about each state).
sample(x, size = 16)
Picks 16 random values from x. Without replace = TRUE each value can be picked only once; with it, values are put back and can repeat.
mean(sample(…))
A function inside a function: R runs the inside first (draw the sample), then takes its mean.
rbinom(n, size, prob)
Random binomial: random results for two-outcome events. With size = 1, each of the n results is one 0 or 1, and prob is the chance of a 1, like a coin flip.

Two laws you must be able to explain

  • Law of Large Numbers: the bigger your sample, the closer its mean gets to the true population mean. Flip a fair coin 10 times and you might get 70% heads; flip it 10,000 times and you will get very close to 50%.
  • Central Limit Theorem (CLT): if you take many sample means, their histogram looks like a normal bell curve centered on the population mean, even if the population itself is skewed. Bigger samples make that bell narrower.

Quantiles and the "mystery sample"

quantile(1:100, c(0.25, 0.75))     # 25.75 and 75.25

set.seed(1)
sampleMeans <- replicate(2000, mean(sample(stateDF$population, 16)))
quantile(sampleMeans, c(0.025, 0.975))   # about 2583 and 6137: the middle 95%
mystery <- c(333, 1088, 3699, 3805, 3135, 3390, 99, 1049,
             235, 129, 4299, 3649, 2295, 4663, 1837, 2711)
mean(mystery)                            # 2276

A quantile is a percentile written as a decimal; the median is the 0.5 quantile. To test a mystery sample, build a distribution of sample means from the real population. If the mystery sample's mean falls outside the middle 95%, it probably didn't come from that population. That's statistical inference in a nutshell.

Example: someone gives you the 16 numbers in mystery and says they are the populations (in thousands) of 16 random US states. Is that believable? The middle 95% of the 2000 simulated means of 16 real states runs from about 2583 to 6137, but the mystery mean is only 2276. It falls outside the middle 95%, so the numbers probably did not come from US states.

New in this code
1:100
The colon makes a sequence of whole numbers: 1, 2, 3, … 100.

Returns the cut points you ask for. c(0.25, 0.75) asks for the 25% and 75% points of the sorted data.
sampleMeans
A vector of 2000 sample means, each the mean of 16 random states from stateDF (built in the population card above).
set.seed(1)
Makes the random draws repeatable, so you get the same 2583 and 6137. A different seed gives slightly different numbers.

ggplot2: charts built in layers

  geom_point() +                          # the shape: scatter plot
  ggtitle("Engine size vs highway mpg")

The question: do cars with bigger engines get fewer miles per gallon on the highway? The dots slope downward, so yes: bigger engines tend to mean lower mileage.

  • Three parts: the data, the aes() mapping (x, y, color, fill, size), and the geom_ shape.

Maps and merging

us <- map_data("state")                  # polygon outline points
ggplot(us) +
  geom_polygon(aes(x = long, y = lat, group = group),
               fill = "white", color = "black") +
  coord_map()                             # proper map projection

merged <- merge(myData, us, by.x = "stateName", by.y = "region")
  • myData is your own table with one row per state, such as a stateName column and a population column. The merge adds those values to the map points, so you can color each state. The names must be lowercase, like "new york", to match region.
  • group = group tells ggplot which points belong to the same shape. Without it the outlines turn into spaghetti.
  • A choropleth map colors areas by a value: aes(fill = population).
  • Add points with geom_point(aes(x = lon, y = lat)).
  • Mercator projection keeps shapes and angles right but stretches areas near the poles. Every projection distorts something.
SQL brain: merge() is a JOIN. By default it's an INNER JOIN; add all.x = TRUE for a LEFT JOIN, which fills non-matches with NA.

Part 3 · Weeks 8–10

Linear models and machine learning

The big picture

  • OSEMN is the data science process: Obtain, Scrub (clean, often 50%+ of the work), Explore, Model, iNterpret.
  • Supervised learning learns from labeled data: you know the right answer for past cases, like past house prices or which passengers survived.
  • Unsupervised learning has no labels and finds patterns, as in clustering and association rules.
  • Supervised learning has two jobs. Regression predicts a number (tomorrow's temperature). Classification predicts a category (rain or no rain, high or low revenue).

Linear regression with lm()

The question: do cars that get more oil changes have smaller repair bills, once you allow for how far they were driven? The data frame oil (from the course lecture) has 14 cars, with each car's number of oil changes, miles driven and repair cost in dollars.

oilChanges <- c(3, 5, 2, 3, 2, 6, 6, 4, 3, 2, 0, 8, 7, 8)
repairs <- c(300, 300, 500, 400, 700, 420, 100, 290, 475, 620, 600, 150, 200, 50)
miles <- c(100500, 116000, 136000, 110500, 150500, 117000, 89500,
           99500, 100500, 120500, 106000, 115000, 104000, 98500)
oil <- data.frame(oilChanges, repairs, miles)

lmOut <- lm(repairs ~ oilChanges + miles, data = oil)
summary(lmOut)
#              Estimate  Pr(>|t|)
# (Intercept)    35.72    0.840
# oilChanges    -57.26    5.08e-05 ***
# miles           0.0051  0.00346  **
# Adjusted R-squared: 0.8615
  • Formula: the outcome (dependent variable) goes left of ~; the predictors (independent variables) go right, joined with +.
  • Coefficient (estimate): how much y changes when that x goes up by 1, keeping the others fixed. Here each extra oil change cuts repairs by about $57, and each extra 1,000 miles adds about $5 (0.0051 × 1,000).
  • p-value Pr(>|t|): below 0.05 means the predictor is significant. More stars means stronger evidence.
  • Adjusted R²: the share of variation in y the model explains. Here 0.86 means oil changes and miles together explain 86% of the differences in repair costs. Use the adjusted version to compare models.
  • Predict new cases: predict(lmOut, newDF), where newDF is a data frame of new cars with the same column names as the predictors, here oilChanges and miles.

Exam phrase: "Does X influence Y?" Correlation is not causation, so the model shows a relationship, not proof that X causes Y.

New in this code
lm()
Linear model: fits a regression line. data = oil says which data frame the columns come from.
y ~ x1 + x2
A formula. Read ~ as “is predicted by”; + adds another predictor.
summary(model)
On a model, prints the full report: coefficients, p-values, R² and more.

Training and testing

The rest of Part 3 uses one example: can we predict who survived the Titanic? The data frame titanic has one row for each of the 2,201 people on board, with four columns: Class (1st, 2nd, 3rd or Crew), Sex, Age (Adult or Child) and Survived (No or Yes). R's built-in Titanic table holds the same data as counts.

set.seed(111)                                   # repeatable split
trainList <- createDataPartition(y = titanic$Survived, p = 0.6, list = FALSE)
trainSet <- titanic[trainList, ]                 # 60% to learn from
testSet  <- titanic[-trainList, ]                # 40% held back to check
Dev brain: the training set is your local dev data and the test set is production data the model has never seen. A model that only works on data it trained on is overfitting, like code that passes only the tests you wrote it against.

createDataPartition() keeps the same share of each class in both sets. About 32% of the people survived (711 of 2,201), so the training set (1,321 rows) and the test set (880 rows) are each about 32% "Yes".

New in this code
set.seed()
Fixes R's random numbers so the same rows are picked every time you run the code.
createDataPartition()
From the caret package (library(caret)): picks row numbers for the training set. y is the outcome column to balance on, p = 0.6 means 60%, and list = FALSE returns plain row numbers instead of a list.
titanic[trainList, ]
Keeps the rows whose numbers are in trainList, with all columns.
titanic[-trainList, ]
The minus keeps every row except those, which gives the test set.

Trees and SVMs

cartTree <- rpart(Survived ~ ., data = trainSet)    # decision tree; "." = all columns
mod1 <- ksvm(Survived ~ ., data = trainSet, C = 5, cross = 3, prob.model = TRUE)
pred <- predict(mod1, testSet)                       # "No" or "Yes" for each test passenger

Both models learn from the Titanic training set above how Class, Sex and Age relate to Survived. Then the SVM guesses survival for the test passengers it has never seen.

  • Decision tree (CART, rpart): a chain of yes/no questions, like a big nested if/else. Easy to read.
  • SVM (ksvm): draws the widest possible boundary between classes. The support vectors are the hard cases closest to the line. The kernel trick lets it draw curved boundaries.
  • C is the cost of mistakes, and cross = 3 runs 3-fold cross-validation. The cross-validation error is the best estimate of real-world error, since training error is always too optimistic.
New in this code
rpart()
From the rpart package: builds a decision tree. Survived ~ . means “predict Survived from every other column”.
ksvm()
From the kernlab package: builds a support vector machine. It uses the same Survived ~ . formula.
prob.model = TRUE
Also lets the SVM give a probability for each class, not just a yes/no answer.
predict(model, testSet)
Runs the trained model on new rows and returns its predictions.

Confusion matrix and accuracy

How good are the SVM's survival guesses? Compare them with what really happened. To keep the math easy, suppose the test set had just 100 passengers and the table came out like this:

cm <- table(pred, actual = testSet$Survived)
#      actual
# pred  No Yes
#   No  50  10
#   Yes  5  35
sum(diag(cm)) / sum(cm)      # (50 + 35) / 100 = 0.85
confusionMatrix(pred, testSet$Survived)  # caret does it for you
  • The diagonal holds the correct predictions; everything off it is a mistake.
  • No Information Rate (NIR): the accuracy you'd get by always guessing the most common class. Your model must beat it to be useful. If 80% of cases are "No", 80% accuracy is worthless. Here 55 of the 100 real answers are "No" (50 + 5), so the NIR is 0.55, and 0.85 beats it easily.
  • Sensitivity is how many real "Yes" cases you caught: 35 of 45, or 0.78. Specificity is how many real "No" cases you got right: 50 of 55, or 0.91. (confusionMatrix() treats the first level, "No", as the positive class, so it swaps these two unless you add positive = "Yes".)
New in this code
table(pred, actual = …)
With two vectors, table() counts every combination: predictions down the side, real answers across the top. That grid is the confusion matrix. Naming the second vector actual puts that label over the columns.
diag()
Takes the diagonal of the grid, top-left to bottom-right: the correct predictions.
sum(diag(cm)) / sum(cm)
Correct predictions divided by all predictions, which is the accuracy.
confusionMatrix()
From caret: builds the same grid and prints accuracy, the No Information Rate, a p-value and more. Give it the predictions first, then the real answers.
Week 10

Ethics and association rules (preview)

These two topics come last before the midterm, so this card gives only the key ideas.

  • Ethics: models copy bias in their training data, can be less accurate for some groups, raise privacy issues, and are hard to explain. Decisions about people need fairness checks and human review.
  • Association rules (unsupervised) are "people who buy X also buy Y". Support is how often items appear together, confidence is how often Y appears when X does, and lift above 1 means the link is stronger than chance. Example: a store has 100 receipts; 20 include bread, 25 include butter, and 10 include both. For "bread → butter", support is 10 / 100 = 0.10, confidence is 10 / 20 = 0.50, and lift is 0.50 / 0.25 = 2, so bread buyers are twice as likely as the average shopper to buy butter.

Q5

Why do we test on data the model never saw?

Show answer

To estimate real-world performance and catch overfitting, when a model memorizes the training data but fails on new data.

Why is the cross-validation error a better estimate of real-world performance than the training error in ksvm() output?

Show answer

Training error is measured on data the model learned from, so it's too optimistic. Cross-validation tests the model on parts of the data it didn't train on, which is closer to new, unseen data.

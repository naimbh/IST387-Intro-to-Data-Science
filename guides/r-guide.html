Week 1

What data science is, and your first R

Data science: math + stats + coding + domain knowledge → actionable insights Structured: rows and columns (SQL, CSV) Unstructured: text, images, audio (there's far more of it) OSEMN and CRISP-DM: process models; both iterative SME: subject matter expert

The ideas the exam can ask about

  • The core goal of data science is creating useful, actionable insights that guide decisions, often through machine learning predictions.
  • It is multidisciplinary: databases, statistics, computer science and non-technical skills. Above all, data science is about communicating.
  • OSEMN: Obtain, Scrub, Explore, Model, iNterpret. It loops; you keep going round. CRISP-DM (Cross-Industry Standard Process for Data Mining) is another process model, and it starts with understanding the business.
  • A project starts with understanding the domain: find the SMEs and get them to tell stories about what they do. Anomalies show you either an error in the system or an interesting exception.
  • Real-world uses: outbreak, climate, health (predicting high-risk patients), sports and business analytics (fraud, customer purchases, inventory).

Vectors: R's arrays

Scope: the tricky lecture example

x <- 2
z <- 3
myFunc <- function(z) {
  return(z * x)
}
myFunc(x)          # 4

Trace it: myFunc(x) passes the value 2, so inside the function z is 2. The outside z <- 3 is hidden by the argument. x isn't defined inside, so R looks outside and finds 2. Result: 2 × 2 = 4.

PHP brain: it's like a closure that can read outer variables, and the parameter name always wins over an outer variable with the same name.

Descriptive vs inferential statistics

Descriptive

Describes the data you have. A summary, a fact, not a prediction. Mean, median, sd.

Inferential

Generalizes from a sample to the population, tests hypotheses, and builds predictive models.

Whatever data you have is only a sample, so there is always uncertainty about how well it represents the population.

Center and spread

Central tendency: "what's typical?"
  • Mean: the average
  • Median: the middle value
  • Mode: the most frequent value
Dispersion: "how spread out?"
  • Range: max − min
  • Variance: average squared deviation from the mean
  • SD: square root of the variance, in the original units
v <- c(0, 0, 0, 2, 3, 4, 5)
mean(v)     # 2
median(v)   # 2
# the statistical mode is 0 (it appears 3 times)
mode(v)     # "numeric"   ← TRAP: mode() gives the TYPE, not the most frequent value
New in this code
mode()
Despite its name, it returns the data type ("numeric", "character"). To get the most common value, use names(which.max(table(v))): table() counts each value, which.max() finds the biggest count, and names() reads off its label.

How variance is built: deviations from the mean → square them → add them up (the sum of squares) → divide (variance) → square root (standard deviation).

var(c(2, 4, 6))   # 4   deviations -2, 0, 2 → squares 4, 0, 4 → sum 8 → 8 / (3 - 1)
sd(c(2, 4, 6))    # 2
New in this code
var()
Variance: the sum of squared deviations divided by n − 1 (R treats your data as a sample).
sd()
Standard deviation: the square root of the variance, in the same units as the data.

Why spread matters (the truck example): a company puts each container on its own truck and must pick one truck size for a whole group: 7 tons (cheaper) or 10 tons. The truck must fit the heaviest container. Group A weighs 2, 5 and 5 tons; group B weighs 1, 3 and 8 tons. Both average 4 tons, so the mean suggests 7-ton trucks are fine for both. But B's 8-ton container won't fit, so B needs 10-ton trucks. The spread reveals this: A's range is 3 (sd 1.73), while B's is 7 (sd 3.61), so B has values far from the average. The SD is easier to explain than the variance because it's in tons, not "squared tons".

Sampling and inferential statistics

Population and sample

A population is usually unreachable as a whole: all 1.5 billion iPhones, all US voters, all the beer in the Guinness factory. So we sample, systematically. One random draw is unpredictable; patterns only show up in the long run, over many draws.

LLN vs CLT: know the difference

Law of Large Numbers → accuracy

Increase the number of observations (or replications), and the sample statistic gets closer to the true population value. Many coin tosses → close to 50% heads.

Central Limit Theorem → shape

Increase the size of each sample, and the sample means form a normal bell curve, even if the population is skewed.

Quantiles and the mystery sample

New in this code

Returns the value below which a given share of the data falls. probs = c(0.25, 0.75) asks for the 25% and 75% points.

The whole numbers from 0 to 200 (201 values).
  • Percentile and quartile mark positions. A quantile is the same idea written as a decimal; the median is the 0.50 quantile (the 50th percentile, the 2nd quartile).
  • The mystery sample's mean was 2,276, below the 2.5% cut-off of 2,391. A mean that low would happen only about 2% of the time if it came from the states, so we infer it came from somewhere else.

Statistical inference in four steps:

  1. Build a comparison distribution (many sample means).
  2. Mark the central 95%; everything outside is "extreme".
  3. Compare the new sample's mean with that distribution.
  4. If it lands in the extreme zone, tentatively conclude it came from a different source.

Visualization and ggplot2

Why and how we visualize

  • Vision is the highest-bandwidth sense: fast, parallel, pre-attentive and great at spotting patterns.
  • Visual components: color, size, texture, proximity, annotation and interactivity (selecting, filtering, zooming, animation).
  • Cleveland & McGill (1984) ranked encodings from easiest to hardest to read: position on a common scale (bars, scatter) → position on non-aligned scales → length, direction, angle → area → volume, curvature → shading and color saturation (heat maps).
  • That ranking is why 3D pie charts are "evil": angles and volume are hard to judge, and 3D distorts them further.
  • Most jobs need only three charts: bar, line and scatter. Bar axes should start at zero.
  • Tufte: make the simplest chart that conveys the information. Cut noise and clutter.
  • Choose colors that fit the data, and remember accessibility: about 300 million people have some color blindness. WCAG 1.4.1 says color must not be the only way information is shown.

Maps

Latitude: horizontal circles, 0 = equator, ±90 = poles Longitude: vertical half circles, 0 = Greenwich, US is negative Projection: sphere → flat; always distorts Choropleth: areas filled by a value Geocoding: address → lat/long

Mapping concepts

  • A data-based map needs at least three fields: latitude, longitude, and a value to show.
  • Small areas work like a flat grid; large areas need a projection, and every projection distorts something. Mercator (1569) keeps direction, which is good for navigation, but not distance or area, so Alaska and Greenland look huge.
  • Four kinds of spatial data: point (x, y), line (connected points), polygon (an enclosed area) and raster/grid (a lattice of cells).
  • Vector maps draw lines between points (shapefiles); raster maps are grids of pixels (tile maps). ggplot draws vector maps.
  • Any spatial object can carry attributes: a name, altitude, population and so on.
  • Geocoding APIs: Google Maps, OpenStreetMap (Nominatim).

Regression vocabulary

Same thing, different names (y)

Dependent, outcome, response, predicted, target, criterion variable, regressand.

Same thing, different names (x)

Independent, predictor, explanatory, input variable, feature, regressor.

  • Equation: ŷ = intercept + B₁X₁ + B₂X₂ + … (the 2D version is y = mx + b).
  • Coefficient: "a one-unit change in X gives B units of change in Y", holding the others constant.
  • Least squares: the best line is the one that makes the squared prediction errors as small as possible.
  • An index like "exam #1, #2" is a label, not a predictor.

Week 9

Supervised learning: trees, SVMs and evaluation

Training set: what the model learns from Test set: held back to check it Overfitting: learns the noise Underfitting: too simple NIR: accuracy of always guessing the biggest class

The modeling process

  1. Train on a substantial number of labeled cases.
  2. Test on data the model hasn't seen, which approximates real-world use.
  3. Use the model to predict new cases where the outcome is unknown.

Some models (like SVMs) are hard to explain to managers: they have nothing like a regression coefficient.

Train/test split with caret

library(caret)
set.seed(110)
trainList <- createDataPartition(y = titanic$Survived, p = 0.80, list = FALSE)
trainSet <- titanic[trainList, ]     # 80%
testSet  <- titanic[-trainList, ]    # the other 20%

cartTree <- rpart(Survived ~ ., data = trainSet)
predictValues <- predict(cartTree, newdata = testSet, type = "class")

Support vector machines

  • An SVM finds the boundary with the widest margin between classes.
  • Support vectors are the hardest cases, sitting on the margin, "a cat groomed like a dog". They define the boundary.
  • The kernel trick maps data into more dimensions (2D → 3D) so a curved boundary becomes a flat one. svmRadial is a common kernel.
  • SVMs are black boxes, but they often predict better, which is why we use them.
library(kernlab)

Ethics and unsupervised learning (preview)

The official study guide lists Weeks 1–9 only, so skip this week when you study for the midterm. It stays here for Lab 10 and the final.

Ethical risks of supervised learning (HW 9, step N)

  • Biased training data: a model trained on past decisions copies past discrimination (hiring, lending, policing).
  • Unequal accuracy: a model can work well on average but badly for smaller groups.
  • Proxies: removing race or gender doesn't help if ZIP code or name stands in for them.
  • Black boxes: people can't challenge a decision nobody can explain (SVMs, deep learning).
  • Privacy and consent: personal data used for purposes people never agreed to.
  • Feedback loops: predictions change behavior, which then becomes new training data.
  • What helps: check accuracy for each group, keep humans in the loop for decisions about people, document the data and model, and allow appeals.

Unsupervised learning

  • No labels. The goal is to find structure, not to predict a known answer.
  • Clustering (for example k-means) groups similar cases, such as customer segments.
  • Association rules find "if X then Y" patterns in transactions, as in market basket analysis.

Worked example. Five shopping baskets: {chips, salsa}, {chips, salsa, soda}, {chips}, {soda}, {chips, salsa}. Rule: chips → salsa.

MeasureMeaningHere
SupportShare of all baskets with both items3 / 5 = 0.6
ConfidenceOf baskets with chips, share that also have salsa3 / 4 = 0.75
LiftConfidence ÷ support of salsa alone; above 1 = stronger than chance0.75 / 0.6 = 1.25
SQL brain: support is COUNT(baskets with both) / COUNT(*); confidence is the same count divided by COUNT(baskets with chips).

The ten traps

  1. R counts from 1; a minus index drops.
  2. One string makes the whole vector character.
  3. mode() gives the type, not the most common value.
  4. order() gives positions; sort() gives values.
  5. |> needs parentheses: x |> min().
  6. filter() and slice() renumber rows; base R brackets keep the old labels.
  7. summarize collapses groups; mutate after group_by keeps every row.
  8. NA spreads: use na.rm = TRUE.
  9. Maps: group = group, coord_map(), tolower() before the merge, arrange(order) after.
  10. Accuracy means nothing until you compare it with the No Information Rate.
